### CLIの書き込みとキャッシュ

テスト用vaultのAPIを一時的にラップし、呼び出されたメソッドを記録した。
操作後に元のメソッドへ戻し、イベント監視も解除した。

| 操作               | 観測したAPI     | イベント時の状態                          | ハイライト |
| ------------------ | --------------- | ----------------------------------------- | ---------- |
| `create`           | `vault.create`  | indexへの登録と、最新内容の`cachedRead`   | 0件から2件 |
| `append`           | `vault.process` | indexへの登録と、追記後内容の`cachedRead` | 2件から3件 |
| `delete permanent` | `vault.delete`  | indexからの削除                           | 3件から0件 |

この結果はObsidian 1.13.7での観測である。
OSのファイル操作や同期サービスによる外部編集、別バージョンのキャッシュ動作は未検証である。

### `eval`の戻り値

| 式・操作                                 | 観測結果                           |
| ---------------------------------------- | ---------------------------------- |
| `Promise.resolve("promise-ok")`          | `=> promise-ok`                    |
| 250ミリ秒後に文字列を返すPromise         | 空応答後の処理完了                 |
| `await Promise.resolve("await-ok")`      | トップレベル`await`の構文エラー    |
| `app.vault.create(...)`からの`TFile`返却 | 循環参照エラーとファイル作成の成功 |
| 既存の`TFile`返却                        | 循環参照エラー                     |
| 処理開始後の文字列返却                   | 完了・成功を保証しない開始応答     |

共通関数は、操作ごとのIDと`pending`・`done`・`error`を確認する。
読み取り専用の式だけを空応答時に再試行し、ファイル作成などの変更操作は再送しない。

## プラグイン側の別課題

注釈のあるノートを開いたまま`plugin:reload`すると、閲覧モードとエディタのハイライトが0件になった。
再読み込み前はそれぞれ2件だった。注釈ファイルは残っていた。
[src/main.ts](../src/main.ts)では、storeを作り直した後の更新契機としてファイル操作やactive-leaf-changeを登録している。

追加調査では、sourceとpreviewの両方で、1秒後と5秒後も0件のままであることを確認した。
フォーカスあり・可視状態でも再現し、注釈ファイルの内容は変わらなかった。
CLIでの内容確認を挟まない計測では、再読み込み後の注釈読み取りとactive-leaf-changeは0回だった。
別ノートに移動して戻ると注釈の読み取りが発生し、2件に復元した。
プラグインの無効化・再有効化でも、sourceで同じ症状を確認した。

原因は、新しいstoreに既存ノートの注釈を初期ロードしないことである。
ハイライト導入時の`582ad47`にも同じ初期化漏れがあるが、過去ビルドの実機確認は行っていない。
再現手順、実測結果、コード参照、修正候補を[Issue #2](https://github.com/sotayamashita/obsidian-reading-annotation/issues/2)に記録した。

手順では、再読み込み後にタブを閉じて開き直す前提を明記した。
これは既存ノートの自動復元を合格とする扱いではない。

## skill化の対象

現段階の対象は、このプラグイン専用のE2E検証である。
Obsidianプラグイン全般向けのskillは、専用手順の検証を固めた後の目標とする。

専用vaultの確認、実体の読み込み確認、非同期操作の完了確認、対象leafと表示モードの限定は、他のプラグインでも利用できる。
注釈ファイルの形式、保存先、コマンドID、CSS selector、期待件数は、このプラグイン固有の実例である。
フォーカス、CLIの戻り値、内部APIの挙動には、検証済みバージョンと条件を併記する。
